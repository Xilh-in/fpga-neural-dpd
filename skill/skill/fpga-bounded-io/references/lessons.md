# 故障驱动的排查表

| 触发 | 观察 | 排查步骤 | 停止条件 |
|---|---|---|---|
| 启动日志停止、不能收命令 | Data_Align 在进入循环前等 CAP_DONE | 画出入口控制流；分别强制 done=0/1；检查失败路径是否 return、是否仍打印成功 | MMIO 本身不返回或时钟停：转平台排查 |
| 主机 read 超时，但板仍无响应 | 只改 Python 不能解除 PS 的 RecvByte | 检查固件收包循环；完整包暂存；短包超时不提交；模拟下一条命令 | 迟到字节仍存在：按协议重新建立同步 |
| 小包正常、大包误报超时 | 截止时间小于最低线传输时间 | 计算字节数×线编码位数/baud；区分静默与整体期限 | 波特率/流控未知，不给保证 |
| 二进制中出现 0A | 按行读取数据会截断 | 先读准确字节数，再验证单独的尾标志 | 长度定义不明，先补协议表 |
| 长命令/空命令随机出错 | 原 C 缺 NUL，8 位长度计数，argc 累加 | 容量检查、NUL、每次重置、限制 token、空命令跳过 | 原函数仍未校验数值范围，应逐项补齐 |

以上排查顺序来自本项目的软件恢复。通用 C 模板没有自动恢复策略，不能声称解决了时钟、复位、CDC 或总线响应错误。
