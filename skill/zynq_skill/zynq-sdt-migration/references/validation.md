# 验证范围与结果

整理日期为 2026-10-26。区分已有开发验证与本技能包新增的软件检查，避免将不同证据混为同一项实验。

## 1. 已有板上验证

| 项目 | 记录 |
|---|---|
| 器件 | xc7z100ffg900-2 |
| PS 平台 | Cortex-A9 standalone，SDT BSP |
| 工具 | Vivado/Vitis 2025.2 |
| 主要修改 | 保留 no-OS 逻辑总线编号，在适配层映射到 BSP 基地址，调整选择分支，并清零实例、检查返回值 |
| 结果 | 平台初始化为 0，时钟及射频器件初始化成功，TX/RX 本振读回 800 MHz |
| 辅助功能验证 | TX 直接连接 RX 的一次 1024 点采集，去均值后的归一化复相关系数幅值约 0.9986 |

故障和成功日志的关键行分别位于 [失败摘录](../examples/observed_init_failure.log) 和 [成功摘录](../examples/observed_init_success.log)。它们摘自开发者已提供的实际串口输出，省略了中间行，不是完整原始日志，也不是预期输出模板。本次打包过程中没有重新连接硬件或重复执行这些板测。

SPI 编号超范围具有实际 no-OS 源码及先前软件复现依据。清零、返回值检查等修改与主修复一起完成，未分别做单因素板测，不能将恢复效果独立归因于每一处辅助修改。

## 2. 本技能包新增的软件验证

实际执行环境为 Python 3.12.14。脚本使用 Python 3.10 起支持的语法及标准库，但未在每个 Python 小版本上单独执行。执行命令如下，实际输出保存在 [软件自检日志](offline_validation.log)。

```text
python scripts/verify_bundle.py
```

验证内容包含技能入口和相对引用、17 项 Python 单元测试，以及 4 种 CLI 退出行为。单元测试中的多个子情形不额外计作独立测试项。

| 检查内容 | 预期行为 |
|---|---|
| SDT 的逻辑编号 0 与显式基地址映射 | PASS |
| 将基地址误填为 no-OS 逻辑编号 | 检出范围错误 |
| 多控制器、未映射、重复编号和重复地址 | 分别通过正确映射或检出冲突 |
| 编号、地址、时钟和布尔类型边界 | 检出非法配置 |
| SDT 与非 SDT 查找类型 | 分别校验相应约定 |
| BSP 别名及 no-OS 上限核对 | 解析简单宏并检出数值冲突 |
| 冲突定义、宏环、表达式和八进制 | 拒绝猜测，返回输入限制 |
| CLI 正确、故意错误、非 SDT 和缺少文件 | 分别返回 0、1、0、2 |

构造的 `example_*.h` 与三个 JSON 是软件夹具，不声称来自独立板卡。另用当前实际 BSP 头文件和 no-OS 头文件核对了声明的 SPI 基地址与编号上限；输出见 [实际头文件检查](actual_header_check.json)。该检查仍不访问硬件，也不证明 C 调用路径。

另外完成了一次基于故障源码的只读技能执行回放，摘要见 [回放记录](skill_replay.md)。用于分析的源码指纹见 [源码标识](source_evidence.json)。这是同一案例的独立上下文回放，不是另一项目迁移或新的板测。

- 第二块开发板、其他队伍工程和跨处理器部署。

- 自动修改驱动、自动编译、自动下载和无人值守板级恢复。
- 神经网络内部数值正确性、外接放大器补偿效果与性能优化。
- JESD204 IP 任意跨版本替换和完整硬件构建的可复现性。

陌生队伍可依据同一工作流和配置契约复用，但必须使用自己的源码和板测结果完成本平台的验证。软件检查 PASS 不等于工程或板卡功能通过。
