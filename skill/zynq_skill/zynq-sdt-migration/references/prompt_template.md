# 调用提示词模板

以下内容是根据已完成的排查过程提炼的使用模板，不是历史对话的逐字导出。

## 模板一，定位初始化失败

```text
使用 zynq-sdt-migration 技能分析当前 Zynq standalone 工程。

工具版本为 [版本]，处理器为 [型号]。
实际编译命令中的 SDT 状态为 [已定义、未定义或尚未确认]。
当前第一个可复现现象为 [编译错误或启动日志]。

附件包括当前 BSP 的 xparameters.h、配置表和 LookupConfig 实现，
no-OS SPI 通用层、平台适配层、应用入口及初始化日志。
我提供的可运行基线及其硬件配置为 [如有则说明]。

先确认实际生效的源码和条件编译分支。
逐层追踪设备标识与返回值，区分总线编号和基地址。
给出有源码依据的结论、尚未确认的假设和最小修改位置。
先选择一次能够区分主要原因的验证，不要反复执行无关检查。
不要根据 PLL 超时文字直接认定外接时钟有问题。
不要把软件模拟写成板上测试，不补写未执行的实验。

输出原因、依据、修改、验证结果和适用边界。
```

## 模板二，复用到其他项目

```text
请读取 skill.md 和 references/migration_guide.md，将工作流用于我的工程。
先判断目标平台、no-OS 结构和 BSP 接口是否符合适用条件。
依据我提供的实际源码填写 SPI 配置契约，并运行静态检查。
清楚说明静态检查不能证明哪些运行行为。

针对每一处建议修改，说明它属于应用层、通用层、适配层还是 BSP。
优先在适配层完成接口转换，保留通用层的逻辑总线编号。
若证据不足，只指出完成当前判断所缺少的具体文件或输出。
使用 references/result_template.md 组织结果。
```

## 建议提供的材料

仅提供足以检查当前问题的源码和日志。不要上传工具安装目录、无关工程或凭据。先保留可运行基线，再进行修改。

在支持标准技能目录的 AI 工具中，可按该工具的说明加载整个 `zynq-sdt-migration` 文件夹。其他工具可直接将 skill.md、相关参考文件和当前工程材料一起作为上下文。该技能不依赖某一个特定 AI 产品的工具接口。
